# End-to-end audit — 30 days
**Date:** 2026-08-17 · **Scope:** 51 commits + 116 uncommitted files · **Method:** three parallel code audits, each finding independently re-verified against the source

---

## Verdict

The features work. The **numbers** and the **boundaries between properties** do not, in specific places. Three revenue figures on screens used daily are overstated, and five tabs show all five properties' data regardless of which property is selected.

Nothing here is cosmetic. Every P1 item is either a number acted on or data crossing a boundary the owner explicitly set.

## P1 — Wrong numbers (verified line by line)

### 1. Revenue (YTD) includes the entire forward book
`src/lib/finance.ts:273-275`
```ts
const ytd = bookings.filter(
  (b) => isRevenueCounting(b) && b.arrival && parseISO(b.arrival) >= yearStart
);   // no upper bound
```
No `<= now`. Every future reservation already on the books — rest of this year *and* 2027 arrivals — is counted as year-to-date revenue.

Confirmed as a bug rather than intent: MTD two files away *does* bound the top (`executiveReport.ts:213`), and `bookingPace` exists as the separate forward-looking metric.

**Contaminates:** dashboard "Revenue (YTD)", the daily email, revenue-by-channel pie, YTD avg nightly rate, avg length of stay.

### 2. Revenue MTD counts cancelled bookings
`src/lib/executiveReport.ts:212-215`
```ts
const mtdBookings = bookings.filter(
  (b) => b.arrival && new Date(b.arrival) >= monthStart && new Date(b.arrival) <= now
);   // missing isRevenueCounting
```
The only revenue reduction in the codebase missing that gate — `revenueTodayGross` twelve lines below has it. Cancelled reservations add their full amount. Relevant: cancellation rate is 9.9% on Colombia, 17.6% on Alva.

**Contaminates:** daily email, WhatsApp digest, AI COO narrative, `totalRevenueMtdGross`.

### 3. Expense approval total adds COP to USD
`src/components/TeamExpenseRequests.tsx:211,234`
```ts
const pendingTotal = waiting.reduce((s, r) => s + (r.estimatedAmount ?? 0), 0);
… {money(pendingTotal, "USD")} estimated
```
The submission form offers COP (`:325`), individual rows respect currency (`:412`), the rollup discards it. One 500,000 COP request (~$125) makes the banner read **$500,125**. On the screen used to decide what to approve. `BillPayExplorer.tsx:89-94` already does this correctly — the right pattern exists, it just wasn't used.

## P1 — Access control

- **`/api/reports/executive`** (`route.ts:13`) — no role check and no property group. A team member can fetch **whole-portfolio financials** for all five properties. The Reports *page* is blocked; its API is not.
- **`/api/debug/send-test-report`** — same data, and it **actually sends** the report. A GET with a real side effect, so the write gate can't stop it.
- **`/api/bills`** — readable by a team session. `/api/bill-pay/*` is blocked; `/api/bills` was missed.
- **~12 more admin-tab GETs** reachable by team sessions (approvals with guest message bodies, marketing contact PII, revenue, reputation, vendors, maintenance, billing status).

Root cause is structural: `proxy.ts:114-137` blocks admin **pages** but only three API prefixes by hand. The fix is to derive API blocks from page blocks.

- **`/api/webhook` has no authentication at all.** Anyone can POST forged OwnerRez events — injecting fake guest messages and bookings, triggering Anthropic spend and WhatsApp approval texts.
- **`/api/whatsapp/webhook` POST does no `X-Hub-Signature-256` check**; it trusts the `from` field in attacker-controlled JSON. A forged POST claiming your number can approve a pending draft and send a real reply to a real guest.
- **Fail-open property access** — `propertyGroups.ts:48-52` returns **all** groups when the access list resolves empty, and call sites use `.catch(() => null)`. A transient DB error silently becomes full access.

## P2

- `BillPayExplorer.tsx:13-17` — when the FX rate hasn't loaded or the endpoint fails, COP bills sum unconverted into a USD total (real COP bills exist: Nukak, 3,777,296 COP → would display as "$3,777,446").
- `api/team-expenses/route.ts:213` — negative `actualAmount` accepted; `estimatedAmount` correctly rejects negatives.
- `api/team-expenses/route.ts:200` — completion with a spend amount isn't gated on approval; a declined request can be marked complete.
- `pendingDrafts.ts:311` — response times written to an un-namespaced key, read from a namespaced one. Colombia's metric is contaminated; the other four are permanently empty.
- `cron/check-messages` — `getBookings`/`getGuests` unscoped, so AI drafts and new-booking alerts only ever cover Colombia. The other four properties' approval queues can never populate.
- Cross-property writes via unvalidated `bookingId` in `api/management/activities` and `booking-ops`.

## What is clean (verified, not assumed)

- **Extras / commission** — derived not stored, rounding correct, only house share added to revenue, no double-counting across dashboard + report, negative commission rejected server-side.
- **Blocks and cancellations in `finance.ts`** — Pompano's 233 iCal blocks cannot inflate revenue or occupancy. Every aggregator gates on `isRevenueCounting`.
- **RevPAR = ADR × Occupancy** — holds; all three read the same accrual window.
- **Cents vs dollars** — every `_cents` value that reaches a screen is divided by 100. No float-where-integer-intended found anywhere.
- **Recurring bills** — double-payment impossible (`unique (recurring_bill_id, period)` + `on conflict do nothing`); "all bills paid" logic correct.
- **Currency toggle** — correctly Colombia-only; display-only; re-conversion impossible by construction.
- **Privilege escalation** — none found. `api/settings/users` gates every method on CEO independently of middleware; self-demotion and self-delete guards present; role lives in an HMAC-signed token.
- **Redis namespacing** — clean except `revenueManager` (above).
- **`unstable_cache`** — clean; every wrapped function takes the property group as a real argument.
- **Migrations** — 35 files, 35 applied, no drift. Typecheck clean. Email verified and sending.

This is the cheapest thing on the list to fix and the most expensive to be wrong about.
